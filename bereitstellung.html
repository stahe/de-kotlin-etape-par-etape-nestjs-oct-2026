    12. Bereitstellung

    Während der Entwicklung installiert [Android Studio] (oder [gradlew installDebug]) die „Debug“-Version der Anwendung: mit einem automatisch erzeugten Debug-Schlüssel signiert, der den Debugger aktiviert. Zur Bereitstellung wird die „Release“-Version erstellt.

    12.1. Die Produktionsversion der Anwendung

    1. Erstellen Sie die Anwendung und geben Sie dabei die Adresse des Produktionsservers an. In einem Eingabeaufforderungsfenster, das im Ordner [rdvmedecins_kotlin] geöffnet ist:
    1
    gradlew assembleRelease -Pserver=https://rdvmedecins.example.com

    [Gradle] kompiliert den [Kotlin]-Code zu „Bytecode“ und dann zu [Dalvik]-Code (dem Format der [.dex]-Dateien, ausgeführt von der virtuellen Maschine von [Android], [ART]) und verpackt alles – zusammen mit den Ressourcen und Bibliotheken – in eine APK-Datei: das Installationsformat für [Android]-Anwendungen. Anders als bei [Flutter] muss keine Engine eingebettet werden: Die Oberfläche wird von [Compose] gerendert, einer Bibliothek wie jede andere. Die entstehende Datei [app/build/outputs/apk/release/app-release-unsigned.apk] ist wenige Megabyte groß.

    Der Block [buildTypes { release [ ... ] }] in [app/build.gradle.kts] konfiguriert diese Version. Dort können Sie den Optimierer [R8] ([optimization [ enable = true ]]) aktivieren: Er entfernt ungenutzten Code aus den Bibliotheken und kürzt die Namen, was die Größe der APK verringert. Anschließend müssen Sie ihm mitteilen, was der Serializer per Reflection findet und beibehalten werden muss (die Regeln für [kotlinx.serialization] werden mit der Bibliothek geliefert), und die optimierte Version TESTEN.

    1. Signieren Sie sie. [Android] installiert nur SIGNIERTE Anwendungen. Am einfachsten verwenden Sie dazu [Android Studio]: Das Menü [Build / Generate Signed App Bundle or APK] erstellt den Entwicklerschlüssel (eine passwortgeschützte „Keystore“-Datei, die Sie sicher aufbewahren müssen: Alle Aktualisierungen der Anwendung müssen mit ihr signiert werden), erstellt dann die APK und signiert sie. Sie können die Signatur auch in [app/build.gradle.kts] definieren (Block [signingConfigs]), indem Sie die Passwörter aus den Eigenschaften von [Gradle] lesen, statt sie fest einzucodieren.

    2. Installieren Sie sie. Bei einem an den Rechner angeschlossenen Telefon (USB-Kabel, USB-Debugging aktiviert):

    1
    adb install app-release.apk

    Sie können die APK-Datei auch auf das Telefon kopieren und öffnen: [Android] bittet Sie dann, die Installation von Apps „aus unbekannten Quellen“ zu erlauben.

    1. Für die eigentliche Veröffentlichung:

    2. [Google Play Store] verlangt statt einer APK ein „Android App Bundle“: [gradlew bundleRelease] oder dasselbe Menü wie in [Android Studio]. Google erzeugt die auf jedes Telefon zugeschnittenen APK-Dateien;

    3. Name und Symbol der App werden in [res/values/strings.xml] ([app_name]) und [res/mipmap-*/] (Menü [New / Image Asset] von [Android Studio]) konfiguriert;
    4. [versionCode] (eine ganze Zahl) muss bei jeder Veröffentlichung erhöht werden; [versionName] ist die angezeigte Version;
    5. der Server muss auf HTTPS umgestellt werden (Passwörter werden übertragen), und die Zeile [android:usesCleartextTraffic="true"] wird aus dem Manifest entfernt;
    6. das Token wird in [SharedPreferences] gespeichert, einer privaten Datei der Anwendung. Für mehr Sicherheit kann es mit dem „Keystore“ von [Android] verschlüsselt werden (Bibliothek [androidx.security]).

    12.2. Der Produktionsserver

    Vergessen Sie in einer Live-Produktionsumgebung nicht die Datei [.env] auf dem Server:

    • ein langes, zufälliges [JWT_SECRET];
    • ein leeres [CAPTCHA_TEST];
    • [COOKIE_SECURE=true], wenn die Website über HTTPS ausgeliefert wird (was der Fall sein muss). Der mobile Client sendet das Cookie unabhängig von dieser Option: Sie wird vom Browser durchgesetzt;
    • [TRUST_PROXY=true], wenn der Server hinter einem Proxy steht ([nginx] ...), damit die Versuchsbegrenzung die tatsächliche IP-Adresse der Clients sieht.

    Anschließend starten wir den kompilierten Server: [npm run build], gefolgt von [npm run start:prod].
