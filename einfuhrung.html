    Dieses Dokument ist ein Produkt der KI Claude von Anthropic. Es adaptiert den Kurs „Schritt-für-Schritt-Einführung in das Mobile-Framework Flutter“ – einschließlich seiner Gliederung, der 25 Beispiele, des Servers und der Fallstudie – und ändert das verwendete Werkzeug:

    • Im Kurs [Flutter] wird die Anwendung in [Dart] geschrieben, mit einem Framework, das jedes Pixel auf dem Bildschirm selbst zeichnet, und derselbe Code erzeugt eine [Android]-, [iOS]- oder Web-Anwendung;
    • In diesem Kurs ist die App eine [Android]-NATIVE App, geschrieben in [Kotlin] (der seit 2019 von Google für Android empfohlenen Sprache) mit [Jetpack Compose], der deklarativen UI-Bibliothek von Android.

    Der Server bleibt dagegen unverändert: Es ist der JSON-Server [RdvMedecins], geschrieben in [NestJS], der bereits von den Clients in React, Vue.js, Angular und Flutter verwendet wird. Auch die Bildschirme kennen die Leser dieser Kurse: Anmeldung mit CAPTCHA, der Terminkalender eines Arztes, ein Buchungsfenster, das Patientenportal, die Verwaltung von Ärzten und Kunden, die Kontoerstellung sowie Unterstützung für Französisch und Englisch.

    Die 25 Beispiele haben dieselben Nummern wie die des Kurses [Flutter] (und der Kurse React, Vue.js und Angular): Leser, die mit einem dieser Frameworks vertraut sind, finden jedes Konzept an seinem gewohnten Platz. Wenn ein Konzept aus [Flutter] in [Compose] kein direktes Äquivalent hat, zeigt das Beispiel den in [Android] üblichen Ansatz (ein Formular aus gewöhnlichen Klassen, Ressourcen [strings.xml] für Texte, Deep Links statt Webadressen ...).

    Zu diesem Thema gibt es bereits einen Kurs: Ein Client-Server-Beispiel - Kotlin Android / NestJS (2026), der von Anfang an einen vollständigen Client vorstellt. Dieses Dokument geht anders vor: Wir lernen [Compose] Schritt für Schritt anhand kleiner Beispiele kennen, bevor wir uns an den vollständigen Client wagen; und der Server wird als Blackbox behandelt, von der uns nur die API und das JSON interessieren.

    Die Grundlagen der Sprache [Kotlin] (Klassen, Datenklassen, Nullbarkeit, Lambdas, Erweiterungsfunktionen, Collections) werden als bekannt vorausgesetzt: Sie werden im Kurs Kotlin behandelt. Die Sprachmerkmale, die für [Compose] besonders relevant sind (Funktionen als Parameter, abschließende Lambdas, Delegation mit [by], versiegelte Schnittstellen, Coroutines), werden in den Beispielen bei ihrer Verwendung jeweils wiederholt.

    Claude hat den gesamten Code geschrieben, kompiliert und mit Erlaubnis des Prüfers auf einem [Android]-Emulator auf dessen Computer ausgeführt; die Screenshots wurden bei diesen Läufen aufgenommen.

    1.1. Die Rolle von Android und Compose in einer Client-Server-Anwendung

    Die Anwendung besteht aus zwei Teilen, die ausschließlich über HTTP-Anfragen miteinander kommunizieren:

    • 1: Die [Android]-Anwendung, die auf dem Smartphone läuft, sendet eine HTTP-Anfrage an den Server, zum Beispiel [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: Der Server antwortet mit JSON-Daten: dem Terminkalender dieses Arztes für diesen Tag. Er erzeugt keinerlei Seiten;
    • 3: Anhand dieser Daten aktualisiert [Compose] den Bildschirm des Smartphones.

    Das ist genau die Architektur der Clients in [React], [Vue.js], [Angular] und [Flutter]: Der einzige Unterschied besteht darin, was die Anzeige erzeugt. [Jetpack Compose] beruht auf denselben Konzepten wie [React] und [Flutter]:

    • Der Bildschirm wird durch FUNKTIONEN beschrieben: Eine mit [@Composable] annotierte Funktion beschreibt einen Teil der Oberfläche (einen Text, eine Schaltfläche, eine Spalte, einen ganzen Bildschirm), indem sie andere [@Composable]-Funktionen aufruft. Sie bilden einen Baum;
    • die Oberfläche ist eine Funktion des Zustands: Wenn sich ein beobachteter Wert ändert (ein „Zustand“, [mutableStateOf]), führt [Compose] die Funktionen, die ihn lesen, erneut aus – das ist die RECOMPOSITION – und aktualisiert den Bildschirm. Wir schreiben nie Code, der den Bildschirm verändert: Wir beschreiben den Bildschirm als Funktion des Zustands;
    • eine moderne Sprache, [Kotlin], kompiliert für die virtuelle Maschine von [Android]: Ihre Lambdas, Erweiterungsfunktionen und Coroutines machen diesen Schreibstil natürlich.

    Anders als [Flutter] ist [Compose] spezifisch für [Android] (eine Variante, [Compose Multiplatform], existiert für andere Plattformen, wird hier aber nicht behandelt). Dafür ist die Anwendung eine „ganz gewöhnliche“ [Android]-Anwendung: Sie nutzt direkt die Bibliotheken von Google ([Jetpack]) und die Systemdienste (Anwendungssprache, Activity-Lebenszyklus, Passwortmanager usw.).

    Wie [Flutter] ist [Compose] kein „Alles-in-einem“-Framework für die Kommunikation mit einem Server: HTTP-Client, Navigation und gemeinsamer Zustand werden von Bibliotheken bereitgestellt. Dieser Kurs verwendet die von Google empfohlenen ([Jetpack]: Navigation, ViewModel, DataStore, AppCompat) und die am weitesten verbreiteten Bibliotheken des [Kotlin]-Ökosystems ([OkHttp], [kotlinx.serialization]).

    1.2. Verwendete Werkzeuge

    Die Beispiele wurden mit den folgenden Werkzeugen geschrieben und getestet:

    • [Android Studio] (Version Quail 2026.1), die Entwicklungsumgebung von Google: Editor, SDK [Android], Emulator. Sie enthält ein eigenes JDK ([JBR] 25), das für [Gradle] verwendet wird;
    • [Gradle] 9.6 und das [Android] (AGP)-Plugin 9.4, die die Anwendung kompilieren. Das [Android]-Plugin 9 selbst enthält die Unterstützung für [Kotlin] 2.2;
    • ein [Android]-Emulator (ein Pixel 8, [Android] 17, API 37) oder ein echtes, an den Computer angeschlossenes [Android]-Smartphone;
    • das DBMS [MySQL] (oder [MariaDB]), zum Beispiel das von [Laragon] unter [Windows], und [Node.js]: Beides ist für den JSON-Server erforderlich, ab dem Kapitel, in dem er vorgestellt wird;
    • das Kommandozeilenwerkzeug [curl], das die rohen HTTP-Antworten anzeigt.

    Die verwendeten Bibliotheken sind für jedes Projekt in der Datei [gradle/libs.versions.toml] deklariert: „BOM“, [Compose] 2026.02 (Material 3), [Navigation Compose] 2.9, [Lifecycle] 2.9 (ViewModel), [DataStore] 1.1, [AppCompat] 1.7, [OkHttp] 4.12, [kotlinx.serialization] 1.9, [AndroidSVG] 1.4.

Die Uhr in der Statusleiste ist auf 10:00 Uhr eingefroren (der „Demo-Modus“ von [Android]).

    1.5. Inhalt des Dokuments

    • Erste Schritte (Beispiele 01 bis 09): eine Activity, die [@Composable]-Funktionen, der Zustand ([remember], [mutableStateOf]), Ereignisse, Eingabefelder, ein Reducer, Validierung, ein wiederverwendbares Formular, Formatierung;
    • Komponenten (10 bis 16): Parameter, Funktionen mit Parametern, Komposition (Inhalt innerhalb von Parametern), Lebenszyklus und Effekte, [CompositionLocal], wiederverwendbares Verhalten (Animationen, [remember...]-Funktionen), Bestätigungsfenster;
    • Navigation (17 und 18): [Navigation Compose], typisierte Routen, Parameter, Deep Links, Guards;
    • Asynchrone Operationen und gemeinsamer Zustand (19 und 20): Coroutines, [Flow], Debounce, veraltete Antworten, [ViewModel], [DataStore];
    • Internationalisierung (21): Ressourcen [strings.xml], Pluralformen, Anwendungssprache;
    • Der Server, eine Blackbox: Installation des JSON-Servers, seine API, [curl]-Beispiele;
    • Kommunikation mit dem Server (22–25): [OkHttp], die Serveradresse, der Token-Cookie, eine Zugriffsschicht auf die API, ein ViewModel, Serverfehler;
    • Fallstudie: Der [Android]-Client für die Anwendung [RdvMedecins];
    • Bereitstellung: die signierte Anwendung (APK), der Produktionsserver.

    Jedes Beispiel wird mit seinem vollständigen, kommentierten Code und Screenshots seiner Ausführung präsentiert. Der Code selbst ist ausführlich kommentiert: Diese Kommentare sind Teil des Kurses.
